01 / POR QUE ISSO IMPORTA?

O perigo nem sempre está onde você olha.

Credenciais podem acabar no código durante testes e configurações. Se forem publicadas, podem expor serviços, dados ou ambientes. O SecurePath foi criado para tornar esses indícios mais fáceis de perceber.

04 / O QUE ELE ENCONTRA?

Sete maneiras de perceber algo suspeito.

Nem todo indício é uma credencial válida. Cada regra procura um formato textual específico — e cada resultado precisa ser interpretado.

07 regras
SEC001 / REGEX
AKIA

AWS Access Key ID

Procura identificadores de chave de acesso AWS que começam com AKIA.

FORMATO RECONHECIDOAKIA + 16 caracteres alfanuméricos
O que isso não comprova?

Não confirma que a chave existe ou está ativa.

05 / POR DENTRO DO ARTEFATO

Simples na execução. Intencional no projeto.

O SecurePath não precisa de nuvem, conta ou instalação de pacotes adicionais. Seu funcionamento usa componentes nativos do Python.

PY◆◆
UMA ESCOLHA DE ARQUITETURA

Python Standard Library

argparse trata parâmetros, pathlib representa caminhos, os percorre pastas, re busca padrões e json estrutura relatórios.

⌘

Executa sem internet

Os arquivos são processados no ambiente local. O Git só é necessário se você optar por clonar o repositório.

◈

Cuida da saída

Os alertas trazem regra, categoria, arquivo e linha, mas não exibem o valor detectado.

↗

Integra-se a scripts

O modo JSON permite processamento automatizado; --fail-on-findings sinaliza alertas com código de saída 1.

01 / IMPLEMENTADO

Três novas capacidades

Recursos presentes no código atual, com benefícios esperados — ainda sem benchmark de desempenho.

PARALELISMO

Mais arquivos, em paralelo.

O parâmetro --workers define de 1 a 64 threads. Cada tarefa analisa um arquivo e a thread principal agrega os resultados, que são ordenados ao final.

Benefício esperadoReduzir o tempo de espera em cargas com muitos arquivos e operações de leitura.
Não há ganho de velocidade comprovado.
{ }
EXTENSIBILIDADE

Regras do seu projeto.

--rules-file acrescenta até 100 expressões regulares por arquivo JSON, com IDs únicos, categorias e validação da configuração. As sete regras nativas continuam ativas.

Benefício esperadoAdaptar a detecção a padrões internos sem editar o núcleo Python.
Use apenas expressões regulares confiáveis.
✓×✓
CONFIGURAÇÃO

Controle o que entra.

--exclude-dir permite excluir diretórios adicionais por nome e pode ser repetido. Complementa os filtros padrão e evita percorrer pastas irrelevantes.

Benefício esperadoReduzir trabalho desnecessário e adaptar a análise à estrutura do projeto.
Diretórios excluídos não são inspecionados.

A fila admite até duas tarefas pendentes por worker (incluindo tarefas em execução). A representação não mede velocidade nem uso total de memória.

04 / PROPOSTAS DE EVOLUÇÃO

Próximos passos recomendados

07 / LIMITES E USO RESPONSÁVEL

Um alerta é uma pista. Não um veredito.

Regex identifica padrões textuais, mas não garante autenticidade, validade ou ausência de segredos. Essa distinção faz parte da proposta técnica.

01

Pode haver falsos positivos e falsos negativos.

02

Não analisa histórico Git, arquivos compactados nem conteúdo criptografado.

03

Ignora arquivos acima do limite, links simbólicos e pastas previstas.

04

Uma saída limpa não comprova ausência de segredos.
